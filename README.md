# РМЖ · Карта терапии

Пилот: три препарата, 13 применений, 12 исследований III фазы. Отдельное
применение связано с режимом, популяцией, источником и регистрационной
юрисдикцией. Версии клинических рекомендаций пока не сверены.

## Открыть

Откройте dist/index.html в браузере. Это самостоятельная страница:
данные, оформление и код уже внутри; интернет нужен только при переходе
к первоисточникам. Нажмите на препарат, выберите этап заболевания и
раскройте исследования.

В каждом применении есть раскрываемый блок «Режим терапии»: исходные
дозы, путь и дни введения, последовательность этапов и длительность.
Всего описаны 10 схем для 13 применений; общая схема может использоваться
в нескольких показаниях. Исследовательские схемы отмечены отдельно.
У каждого режима указаны источники и дата сверки — 19.09.2026.

Редукции, премедикация и полный мониторинг в краткие карточки не входят;
ссылки ведут к инструкциям и протоколам. Для EMBER-4 доза и длительность
взяты из первичного дизайна SABCS 2022 / Cancer Research 2023; аннотация
доступна в открытых метаданных издателя через Crossref по указанному DOI.

Верхний слой рекомендаций имеет статус «не сверено». Он не означает,
что соответствующих рекомендаций не существует. Регистрация в пилоте
относится только к FDA/США. Панопухолевые показания T-DXd не включены.

## Что действительно обновляется автоматически

- Статусы, даты и размещение результатов для 12 заданных NCT.
- Ссылки на публикации по полю NCT/Secondary Source ID в PubMed и ссылки
  RESULT, указанные в реестре. Общетекстовый поиск не используется.
- Известные проверенные документы FDA — в рамках точного сопоставления.
- Новые документы FDA по трём препаратам и изменения раздела показаний
  инструкций — как события, требующие сверки.
- Дата проверки, ошибки источников и журнал изменений.

Публикация, завершение исследования или hasResults=true не превращаются
в одобрение. Перечень «результаты в реестре» не является полным перечнем
публично представленных результатов.

Связь записи PubMed с номером NCT не доказывает, что статья представляет
основные результаты этого исследования. В подборку могут попадать
протоколы, обзоры, вторичные анализы и статьи, ссылающиеся на несколько
исследований. Эти записи служат ссылками для чтения и не меняют
клинический или регистрационный статус.

Дозы и расписания находятся в отдельном проверенном разделе regimens
каталога. Они не извлекаются и не меняются автоматически. Дата их сверки
сохраняется отдельно от даты сбора источников. При изменении протокола
или инструкции соответствующий режим нужно сверить и обновить вручную.

Для автоматической смены регистрационного статуса используется
проверенное соответствие «документ — конкретное показание» и контрольная
сумма содержимого. Совершенно новое одобрение сначала попадает на сверку.
После медицинской проверки добавляется правило в data/catalog.json.
Пилот не обещает самостоятельно интерпретировать произвольную новую
инструкцию и менять клинические рекомендации.

## Бесплатный ежедневный запуск

Сценарий .github/workflows/update.yml проверяет источники ежедневно.
Версия для телефона включает начальный проект внутри одного файла:
при первом запуске он создаёт файлы, а затем сохраняет их в репозитории.
При последующих запусках существующие файлы не заменяются вложенным
снимком. Для публикации включите Settings → Pages → GitHub Actions. Он использует публичные HTTP-источники и
стандартный Python, без подписок, платных API и внешних пакетов.

1. Создайте публичный репозиторий GitHub и загрузите содержимое проекта,
   включая папку .github.
2. В Settings → Pages выберите Source → GitHub Actions.
3. В Actions включите workflow «Обновить карту терапии» и запустите его
   через Run workflow.
4. После первого успешного запуска адрес появится в Settings → Pages.
   Повторные проверки назначены на 04:23 UTC ежедневно.

Стандартные GitHub Actions для публичного репозитория и GitHub Pages
доступны на бесплатном тарифе по условиям, проверенным 19.09.2026.
Код и опубликованные сведения будут открыты. Свой домен не требуется.
Workflow не создаёт платные ресурсы, не использует крупные runner-ы
и не включает платные квоты или подписки.

Расписание GitHub может задерживаться, а после 60 дней без активности
репозитория приостанавливается. На странице выводится дата последней
попытки сбора и предупреждение после трёх дней. Проверять состояние
workflow всё равно необходимо.

## Локальная проверка

Нужен Python 3.10 или новее.

    python scripts/refresh.py
    python -m unittest discover -s tests -v
    python scripts/build.py

В GitHub сборка использует --automation-configured, чтобы отличить
подключённое расписание от локального снимка. Эта метка показывает
конфигурацию; фактическую свежесть определяют даты и ошибки источников.

## Медицинская сверка

data/catalog.json содержит вручную проверенные описания и связи,
data/state.json — полученные сведения и историю. Для новой регистрации:

1. Открыть официальный документ, проверить режим, подтип, биомаркер,
   линию, регулятора и дату события.
2. Добавить отдельное применение или уточнить существующее.
3. Добавить правило с точным URL, заголовком, перечнем показаний,
   обязательными фрагментами и контрольной суммой proof_for из core.py.
4. Просмотреть получившееся изменение и повторно выполнить проверки.

Флаг needsReview сохраняется до явной сверки. Для его снятия после
рассмотрения всех событий обновите правило и явно снимите флаг у
соответствующего применения в state.json. Историю не удаляйте.

При недоступности источника предыдущие сведения сохраняются. Отсутствие
нового показания в более старой выгрузке инструкции не отменяет более
позднее официальное решение FDA.

Новые препараты и новые исследования автоматически не добавляются в
клиническую карту: эта версия отслеживает заданный список. Эффекты
лечения и заключение о положительном/отрицательном исходе не извлекаются
без медицинской сверки. Первая и вторая фазы не включены.

## Состав проекта

- web/ — интерфейс.
- scripts/core.py — правила обновления и журнал.
- scripts/refresh.py — сборщик ClinicalTrials.gov, FDA/openFDA, PubMed.
- scripts/build.py — сборка самостоятельной HTML-страницы.
- data/ — проверенный каталог и снимок сведений.
- data/catalog.json, regimens — дозы, графики и источники схем; связь
  с отдельным применением задаётся полем regimenId.
- tests/ — проверки переходов и отсутствия дублей.
- tests/fixtures/imlunestrant-combo.html — текст официального сообщения
  федерального ведомства FDA от 18.09.2026 для воспроизведения события;
  URL указан в каталоге.
- .github/workflows/update.yml — сбор, проверка и публикация.

Первоисточники доступны из карточек. Их собственные условия использования
и ограничения сохраняются. Сведения в пилоте сокращены для отображения;
полную формулировку показания следует читать в первоисточнике.

Официальные технические источники:

- https://clinicaltrials.gov/data-api/api
- https://open.fda.gov/apis/drug/drugsfda/
- https://pubmed.ncbi.nlm.nih.gov/help/#secondary-source-id-si
- https://docs.github.com/en/billing/concepts/product-billing/github-actions
- https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
